# Research: WhatsApp transport options

**Ticket:** wayfinder research — WhatsApp transport options for the agentic WhatsApp SDR
**Research date:** 2026-07-28
**Scope:** RESEARCH ONLY. Facts and sources for the later decision ticket. No recommendation here.
**Context assumed:** VAIF (Brazil), 6 tattoo-artist clients today → tens within 6 months; ~6–12 inbound WhatsApp messages/artist/day; WAHA already self-hosted on a Coolify server.

Primary sources used: devlikeapro/waha docs + GitHub + blog; Meta for Developers documentation (developers.facebook.com/documentation/business-messaging/whatsapp/*) and Meta's published rate-card CSVs; whatsapp.com legal pages; Meta Business Help Center. Note: developers.facebook.com blocks direct scraping; pages were read through a text-extraction proxy and the Internet Archive, and two rate-card CSVs were downloaded directly from Meta's CDN. URLs cited are the canonical first-party URLs.

## 1. WAHA (self-hosted WhatsApp HTTP API, devlikeapro/waha)

### 1.1 Engines and tradeoffs

- WAHA is a Node.js "glue layer" that wraps several community WhatsApp client libraries behind one REST API + webhook interface; the engine is selected with `WHATSAPP_DEFAULT_ENGINE`. API responses and webhook payloads can differ between engines. Source: https://waha.devlike.pro/docs/how-to/engines/
- **WEBJS** — runs a real Chromium/Chrome browser via Puppeteer connected to WhatsApp Web; it is the default engine when `WHATSAPP_DEFAULT_ENGINE` is unset. WAHA describes it as using "a real instance of Whatsapp Web to avoid getting blocked." Source: https://waha.devlike.pro/docs/how-to/engines/
- **WPP** — second browser-based engine (Puppeteer + WhatsApp Web), added in WAHA 2026.3. Sources: https://waha.devlike.pro/docs/how-to/engines/, https://waha.devlike.pro/blog/waha-2026-3/
- **NOWEB** — WebSocket-based (Node.js/TypeScript), no browser; "Not running Chromium saves you CPU and Memory, so you can run more instances on a single server." Requires enabling its "store" to get chats/contacts/messages. Source: https://waha.devlike.pro/docs/how-to/engines/
- **GOWS** — WebSocket-based written in Go; WAHA calls it "a new generation engine …, a future replacement for NOWEB engine." Source: https://waha.devlike.pro/docs/how-to/engines/
- **VENOM** — listed in WAHA's engine docs navigation but not covered in the current engine feature matrices (the comparison tables cover WEBJS, WPP, NOWEB, GOWS). Source: https://waha.devlike.pro/docs/how-to/engines/
- Feature support differs per engine (e.g., `GET /api/screenshot` only works on the browser engines WEBJS/WPP; several group/status/channel endpoints are missing on NOWEB/GOWS). Source: https://waha.devlike.pro/docs/how-to/engines/
- Per-session resource footprint (WAHA FAQ table, per container):

  | Sessions | WEBJS | NOWEB | GOWS |
  |---|---|---|---|
  | 1 | 0.3 CPU / 400 MB | 0.1 CPU / 200 MB | 0.1 CPU / 200 MB |
  | 10 | 3 CPU / 2.5 GB | 1 CPU / 2 GB | 0.5 CPU / 1 GB |
  | 50 | 15 CPU / 20 GB | 2 CPU / 4 GB | 1.5 CPU / 3 GB |
  | 100 | – | 4 CPU / 8 GB | 3–5 CPU / 5 GB |
  | 500 | – | – | 5–8 CPU / 25 GB |

  WAHA "strongly recommends" a minimum 2 CPU / 4 GB RAM server even for a single session. Source: https://waha.devlike.pro/docs/overview/faq/

### 1.2 Session model (how multiple numbers are hosted)

- A **Session** in WAHA = one WhatsApp account (phone number) connected to WAHA; sessions are created by name via `POST /api/sessions` and multiple sessions run inside a single Docker container. Sources: https://waha.devlike.pro/docs/how-to/sessions/, https://github.com/devlikeapro/waha (README quick start)
- Authentication is WhatsApp's standard multi-device pairing: scan a QR code (or request a pairing code) from the phone's app; the session then appears as a linked device under **WhatsApp → Linked Devices** (device name is configurable per session). Source: https://waha.devlike.pro/docs/how-to/sessions/
- Session lifecycle statuses: `STOPPED`, `STARTING`, `SCAN_QR_CODE` (QR must be re-fetched on each refresh), `PASSKEY_REQUIRED`/`PASSKEY_CONFIRMATION_REQUIRED`, `WORKING`, `FAILED` (restart, or logout + start again). Source: https://waha.devlike.pro/docs/how-to/sessions/
- Per-session config supports: multiple webhooks (HMAC, custom headers, retry policy), proxy per session, per-session metadata key-values (WAHA's docs suggest storing "your user or tenant id" — the multi-tenant hook), and ignoring event classes (status/groups/channels/broadcast) to save resources. Source: https://waha.devlike.pro/docs/how-to/sessions/
- Horizontal scaling beyond one container = run multiple WAHA instances on different servers (per FAQ, pointing at a "WAHA Scaling — how to handle 50+/500 sessions" blog post). Source: https://waha.devlike.pro/docs/overview/faq/

### 1.3 Multi-tenancy features and tiers (Core vs Plus/Pro)

- **Tier situation as of 2026-07-28: there are no paid tiers anymore.** Starting with version **2026.6.1** (released 2026-06-21), all former **WAHA Plus** features — unlimited sessions, media messages, all storages (PostgreSQL, MongoDB, S3), built-in security (API keys, Swagger auth), observability — are in the free, open-source **WAHA Core**; the `devlikeapro/waha-plus` image is still published temporarily but is no longer needed. Sources: https://waha.devlike.pro/docs/how-to/waha-plus/, https://waha.devlike.pro/blog/waha-2026-6/, https://waha.devlike.pro/docs/overview/faq/
- The old Core/Plus/PRO Patreon/Boosty tiers were dropped; the only paid thing is a symbolic **Community tier at $5/mo** (Patreon/Boosty/crypto) with "no perks." Historical Plus/Pro pricing is no longer published. Source: https://waha.devlike.pro/blog/waha-2026-6/
- Everything relevant to one-session-per-client multi-tenancy (unlimited sessions, per-session webhooks/metadata/proxy, API-key security) is therefore free today. Sources: https://waha.devlike.pro/docs/overview/faq/, https://waha.devlike.pro/docs/how-to/sessions/
- WAHA also ships an MCP server for AI agents (2026.4) and per-scope API keys (2026.4), relevant to an agentic SDR integration. Source: https://waha.devlike.pro/blog/waha-2026-4/

### 1.4 Stability / ban considerations documented by the project

- WAHA's own disclaimer: "it is not guaranteed that you will not be blocked by using this method. **WhatsApp does not allow bots or unofficial clients on their platform, so this shouldn't be considered totally safe.** For any businesses looking to integrate with WhatsApp for critical applications, we highly recommend using officially supported methods …" Source: https://waha.devlike.pro/docs/overview/introduction/
- WAHA's "How to Avoid Blocking" guidance: **never initiate a conversation — only reply** to received messages; avoid spam-like patterns (identical texts, fixed timing, 24/7 sending); use sendSeen/startTyping/stopTyping to mimic human behavior; "being tagged as spam a few times (5–10) will get you banned"; conversations and being added to contacts make a number "stronger against a ban." Source: https://waha.devlike.pro/docs/overview/%EF%B8%8F-how-to-avoid-blocking/
- Note the alignment/misalignment with VAIF's use case: the SDR works *inbound* leads (reply-only), which matches WAHA's #1 anti-blocking guideline; business-initiated outbound would violate it. Source: https://waha.devlike.pro/docs/overview/%EF%B8%8F-how-to-avoid-blocking/

## 2. Ban risk on unofficial clients — what the ToS says

- **WhatsApp Terms of Service** (consumer ToS, effective Jan 4, 2021, still the current text per the live page as of July 2026), "Acceptable Use Of Our Services": users must not use the services in ways that "(e) involve sending illegal or impermissible communications such as **bulk messaging, auto-messaging, auto-dialing**, and the like; or (f) involve any **non-personal use** of our Services unless otherwise authorized by us." It also forbids: "(a) reverse engineer … our Services; … (e) create accounts for our Services through unauthorized or automated means; … (i) create software or APIs that function substantially the same as our Services and offer them for use by third parties in an unauthorized manner." And: "If you violate our Terms or policies, we may take action with respect to your account, including **disabling or suspending your account**." Source: https://www.whatsapp.com/legal/terms-of-service (read via https://web.archive.org/web/20260727180638/https://www.whatsapp.com/legal/terms-of-service)
- **WhatsApp Business Terms of Service** (last updated Feb 16, 2024), §5 "Restrictions": the company must not "(g) **develop or use any applications that interact with our Business Services without our prior written consent**." §6 "Acceptable Use": no "spam, unsolicited electronic communications …"; "Enforcement": "we have the right to **limit, throttle, suspend, or terminate** Company's account." §4: WhatsApp users may block/report a company, which "could result in WhatsApp suspending or terminating Company's use of our Business Services." Source: https://www.whatsapp.com/legal/business-terms (read via https://web.archive.org/web/20251230101946/https://www.whatsapp.com/legal/business-terms)
- The Business Terms also contain the LGPD hook relevant to a Brazilian agency: the company is the Controller and WhatsApp the Processor for customer contact data under Brazil's Lei Geral de Proteção de Dados (Law 13.709/2018). Source: https://www.whatsapp.com/legal/business-terms (§7, via the same archived copy)
- WAHA (project-authored) corroborates the risk and gives the low-volume mitigations summarized in §1.4 (reply-only, human-like pacing, avoid reports). Sources: https://waha.devlike.pro/docs/overview/introduction/, https://waha.devlike.pro/docs/overview/%EF%B8%8F-how-to-avoid-blocking/
- Adjacent, newer policy fact: WhatsApp's **Business Solution Terms** (updated Jan 15, 2026) define "**AI Providers**" (providers of LLMs / general-purpose AI assistants) and restrict them to offering general-purpose assistants on the Business Platform only where Meta is legally required to permit it. Whether a business-specific SDR agent falls under that definition is a question for the decision ticket; the definition is quoted on Meta's AI-Provider pricing page. Sources: https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing/ai-providers/, https://www.whatsapp.com/legal/business-solution-terms/

## 3. Official WhatsApp Business Platform (Cloud API)

### 3.1 Pricing model (as of 2026-07-28) and Brazil numbers

- **Model:** Since **July 1, 2025** Meta charges **per delivered template message** (conversation-based pricing is deprecated). Rates depend on template category (marketing / utility / authentication) and the recipient's country. Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing/
- **What's free today:** all **non-template (service) messages** inside an open customer service window (free since Nov 1, 2024), and **utility templates delivered inside an open CSW** (free since Jul 1, 2025). Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing/
- **⚠️ Both change imminently** (announced on the pricing page, days after this research):
  - **Effective Aug 1, 2026** — Meta Business Agent messages (Meta's own AI agent) are charged per token: one global rate of **$2.00 USD per 1M tokens**, ~20–25k tokens/message ≈ **~4–5 USD cents/message**; requires a Meta credit line (monthly invoicing).
  - **Effective Oct 1, 2026** — **service messages** (including messages powered by third-party AI) become chargeable per message, at the same rates as utility/authentication for that market; and **utility templates inside the CSW** stop being free. Rates for service messages will be published by Sept 1, 2026.
  Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing/non-template-messages
- **Actual Brazil rates** (from Meta's own rate-card CSVs, "effective July 1, 2026", downloaded from Meta's CDN via the links on the pricing page):
  - USD card: **Brazil — marketing $0.0625, utility $0.0068, authentication $0.0068** per delivered message.
  - BRL card: **Brazil — marketing R$0.3217, utility R$0.0350, authentication R$0.0350** per delivered message.
  Source (index page linking both CSVs): https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing/ (section "Rate cards and volume tiers"). The Meta Business Agent doc independently confirms the $0.0068 figure: "The 0.68 USD cent message delivery rate is based on the current rate for utility and authentication messages to users in Brazil." Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing/non-template-messages
- **Free entry points (FEP):** when a user messages via a Click-to-WhatsApp ad or a Facebook Page call-to-action button (from the Android/iOS app), and the business responds within 24h, a **72-hour window opens during which ALL messages — including templates — are free**. (FEP does not waive Meta Business Agent token charges.) Sources: https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing/, https://business.whatsapp.com/products/platform-pricing
- **Volume tiers:** utility and authentication rates get cheaper with monthly volume; messages aggregate **per business portfolio, across all of that portfolio's WABAs**, per market–category; tiers reset monthly; only charged messages count. Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing/
- **Brazil billing localization:** effective July 1, 2026 (rollout complete July 16, 2026), eligible Solution Providers/direct businesses with Sold-To country = Brazil create new WABAs in **BRL**, invoiced by Facebook Brasil; such customers must migrate all WABAs to BRL by **June 30, 2027** (after which Meta stops delivering messages from non-BRL WABAs of eligible customers). Meta Business Agent accounts in BRL are marked "Not yet available" (USD or 13 other currencies instead, FX-applied). Sources: https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing/, https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing/non-template-messages
- **Pricing governance:** Meta changes rates at most quarterly (Jan/Apr/Jul/Oct 1) with 1–6 months' notice depending on change type. Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing/
- **AI-Provider pricing policy:** since Feb 16, 2026 Meta charges "AI Providers" (per the Jan 15, 2026 Business Solution Terms definition) for non-template messages in markets where it must allow them; as of May 13, 2026 Meta stopped charging AI Providers in certain markets. This policy is aimed at general-purpose AI assistants, not ordinary business bots; applicability to a bespoke SDR agent is unverified (see Gaps). Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing/ai-providers/
- **Illustrative arithmetic for VAIF's volume (not a recommendation):** at ~6–12 inbound/artist/day, reply-only traffic inside the CSW costs $0 today; post-Oct 1, 2026 the same replies would cost ≈ $0.0068 each ⇒ ≈ **$1.20–$2.45 per artist per month** (30 days × 6–12 msgs × $0.0068), before any template traffic. Rates per sources above.
- For contrast, Meta's own worked example for 1,000 AI-powered replies in Brazil: ~$27 (lower-complexity third-party AI incl. delivery) to ~$97 (higher-complexity), vs ~$40–50 via Meta Business Agent. Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing/non-template-messages

### 3.2 The 24-hour customer service window (CSW)

- A user message (or call) opens a **24-hour** window; each new user message resets the timer. While open, the business can send any free-form message type; after it closes, **only pre-approved template messages** can be sent. Sources: https://developers.facebook.com/documentation/business-messaging/whatsapp/messages/send-messages/, https://developers.facebook.com/documentation/business-messaging/whatsapp/templates/overview/
- Inside the window an agent can send: text (with link previews), image, audio, video, document, sticker, location, contacts, reactions, interactive messages (reply buttons, lists, CTA-URL, Flows, location request), address messages, plus read receipts and typing indicators. Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/messages/send-messages/
- Outside the window: template messages only, each charged per its category rate (marketing always charged; utility charged only outside CSW — and also inside CSW starting Oct 1, 2026). Sources: https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing/, https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing/non-template-messages
- Sending at all requires user **opt-in**. Sources: https://developers.facebook.com/documentation/business-messaging/whatsapp/messages/send-messages/, https://developers.facebook.com/documentation/business-messaging/whatsapp/getting-opt-in/
- Delivery retry TTL: 30 days for most messages, 10 minutes for authentication templates. Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/messages/send-messages/
- Coexistence nuance: messages sent from the WhatsApp Business app are NOT subject to the CSW and don't affect Cloud API pricing/windows (only Cloud API sends are). Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/embedded-signup/onboarding-business-app-users/

### 3.3 Template messages (business-initiated)

- Templates are WABA assets and the only way to message users with no open CSW; each template must be categorized **marketing, utility, or authentication** and is **automatically reviewed at creation**; it must reach status `APPROVED` before use (review "can take up to 24 hours"). Sources: https://developers.facebook.com/documentation/business-messaging/whatsapp/templates/overview/
- Post-approval, quality feedback (blocks/reports/low read-rates) can move templates to Paused/Disabled; there is also template **pacing** (slow rollout to gather feedback) and **per-user marketing template limits** (caps how many marketing templates any one user receives across businesses). Sources: https://developers.facebook.com/documentation/business-messaging/whatsapp/templates/overview/, https://developers.facebook.com/documentation/business-messaging/whatsapp/templates/template-pacing, https://developers.facebook.com/documentation/business-messaging/whatsapp/templates/marketing-templates/per-user-limits/
- Template inventory limits: max 100 new templates per WABA per hour; an **unverified** business portfolio caps each WABA at **250** templates; a **verified** portfolio with an approved display name gets **6,000**. Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/templates/overview/
- **Messaging limits** (business-initiated sends): new business portfolios can message **250 unique users per 24h**; scaling paths (business verification, partner-led verification, or 2,000 delivered template messages/30 days at high quality) raise it to **2,000**, then automatic scaling to **10,000 / 100,000 / unlimited** based on quality and ≥50% utilization. Limits are set at portfolio level and shared across its numbers. Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/messaging-limits/

### 3.4 Phone numbers and WABA structure

- A phone number registered on Cloud API **cannot simultaneously be used with WhatsApp Messenger**; a number already in use with WhatsApp must be **deleted first** (and a banned number must be unbanned via appeal first). Registered numbers still work for ordinary calls/SMS. Exception: the coexistence flow for WhatsApp **Business app** numbers (§4). Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/business-phone-numbers/phone-numbers/
- Number requirements: owned by the business, has country/area code (no short codes), can receive SMS or voice calls (mobile recommended; VoIP "not recommended" for SMS OTP but workable via voice); verification is by SMS/voice OTP code. Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/business-phone-numbers/phone-numbers/
- **Each artist can have their own number + WABA.** Embedded Signup lets each business customer select/create their own business portfolio, select/create a WABA, register and verify their own number, and set a display name; customers own their assets. Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/embedded-signup/overview/
- Phone-number caps: new business portfolios start capped at **2 registered numbers**; business verification (or reaching a 2,000 messaging limit) auto-raises the cap to **20**. Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/business-phone-numbers/phone-numbers/
- **Business verification** (Meta Business Suite, Security Center): confirms the business is a registered legal entity (registered with local authorities, official phone/mailing address) and that the applicant is an authorized representative (verification code to business phone/email, or domain verification). Not all portfolios are offered verification ("Start verification" vs "Ineligible for verification"); WhatsApp Business Platform "may need" verification for certain features. Sources: https://www.facebook.com/business/help/1095661473946872, https://business.facebook.com/business/help/595597942906808
- Verification is also one of the three scaling paths to lift the 250→2,000 messaging limit, and unlocks the 6,000-template cap. Sources: https://developers.facebook.com/documentation/business-messaging/whatsapp/messaging-limits/, https://developers.facebook.com/documentation/business-messaging/whatsapp/templates/overview/
- A display name is required at registration and may require review; Official Business Account (blue check) is a separate optional request. Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/business-phone-numbers/phone-numbers/

### 3.5 Onboarding burden (embedded signup, partner model)

- **Embedded Signup** (Facebook Login for Business + JS SDK) is the standard onboarding surface: it gathers business info, generates the WABA + phone-number assets, grants the partner's app access, and returns WABA ID, phone number ID, and an exchangeable token code; the partner then exchanges the code, registers the number, and subscribes to webhooks. Available in 30 languages incl. Portuguese (Brazil). Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/embedded-signup/overview/
- **Partner models:** **Solution Partner** — must hold a Meta line of credit and shares it with onboarded customers (customers can message immediately; partner is billed). **Tech Provider** — onboarded customers attach their own payment method to their WABA before messaging. Sources: https://developers.facebook.com/documentation/business-messaging/whatsapp/embedded-signup/overview/
- **Onboarding rate limits for the partner:** 10 new business customers per rolling 7 days by default; raised to 200/7d after completing Business Verification + App Review + Access Verification; more requires Meta Business Partner status. Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/embedded-signup/overview/
- The partner app needs **App Review** (advanced access) for `whatsapp_business_management` and `whatsapp_business_messaging` before it can onboard real customers. Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/embedded-signup/overview/
- Embedded Signup **v2 is deprecated on Oct 15, 2026** — new integrations should target v4. Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/embedded-signup/overview/
- Non-partner alternative: a business can self-serve via Meta Business Suite / WhatsApp Manager / App Dashboard to create a WABA and register a number directly. Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/business-phone-numbers/phone-numbers/

## 4. Hybrid path: migrating from WAHA to Cloud API later

What the numbers actually are today: WAHA connects each artist's number as a **linked device** on that number's ordinary WhatsApp / WhatsApp Business app account (QR pairing); the account stays alive on the artist's phone. Sources: https://waha.devlike.pro/docs/how-to/sessions/, https://github.com/devlikeapro/waha

- **Same number, consumer WhatsApp app:** to register that number on Cloud API you must **delete the WhatsApp Messenger account** in the app (Settings → Account → Delete my account); the number "may take up to 3 minutes" to become available, then it can be added and OTP-verified. Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/solution-providers/migrate-existing-whatsapp-number-to-a-business-account/
- **Same number, WhatsApp Business app:** two routes. (a) Delete the account → **messaging history is lost**, and the number can't go back to the Business app unless deregistered from Cloud API. (b) **Coexistence**: onboard via a partner whose Embedded Signup supports "WhatsApp Business app user onboarding" — the number then works **concurrently** in the Business app and Cloud API, with history kept in sync. Requires: Solution Partner or Tech Provider status, Business app version ≥ 2.24.17, and a fixed **20 messages/sec** throughput ceiling on such numbers. Sources: https://developers.facebook.com/documentation/business-messaging/whatsapp/solution-providers/migrate-existing-whatsapp-number-to-a-business-account/, https://developers.facebook.com/documentation/business-messaging/whatsapp/embedded-signup/onboarding-business-app-users/
- **History/portability specifics of coexistence:** contacts sync; 1:1 chat history up to **180 days** back can be synced to the partner (one shot, must start within 24h of onboarding; media only for the last 14 days); **group chats do not sync**; broadcast lists become read-only; disappearing/view-once/live-location disabled; new app-sent messages arrive as `smb_message_echoes` webhooks. Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/embedded-signup/onboarding-business-app-users/
- **Anything stored only on the WAHA side does not migrate** — WAHA session data, WAHA's local message store, and its linked-device pairing are not importable into Cloud API; the only official "history carry-over" mechanism is the coexistence sync above (from the Business app, not from WAHA). Inference from: https://developers.facebook.com/documentation/business-messaging/whatsapp/embedded-signup/onboarding-business-app-users/ (sync source is the app) and https://waha.devlike.pro/docs/how-to/storages/ (WAHA-local storage)
- **Re-onboarding each client** on the official path means, per artist: Embedded Signup flow (Meta/Facebook credentials, portfolio + WABA creation, number OTP, display name) — or the coexistence variant — plus the new-account warm-up state: 250-unique-users/24h messaging limit, template approval cycles, quality monitoring. Sources: https://developers.facebook.com/documentation/business-messaging/whatsapp/embedded-signup/overview/, https://developers.facebook.com/documentation/business-messaging/whatsapp/messaging-limits/
- **Brazil billing wrinkle for a later migration:** WABAs created by Brazil Sold-To partners are now BRL-denominated and invoiced by Facebook Brasil; eligible portfolios must be fully on BRL WABAs by June 30, 2027. Source: https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing/
- **Partner status lead time:** the migration-friendly route (coexistence, credit-line sharing, >10 onboardings/week) requires being a Solution Partner/Tech Provider with App Review completed — an onboarding burden to start well before the migration date. Sources: https://developers.facebook.com/documentation/business-messaging/whatsapp/embedded-signup/overview/, https://developers.facebook.com/documentation/business-messaging/whatsapp/embedded-signup/onboarding-business-app-users/
